# Производительность глобуса / Globe performance

## Первая загрузка, локальная проверка 18 ноября 2026

Сравнение версии 1.14.1 и рабочей сборки на одном компьютере. В Edge использовались экран 412 × 915, DPR 2,625, четырёхкратное замедление CPU, задержка сети 85 мс и скорость загрузки 1 МиБ/с. Локальный HTTP/2-сервер отдавал одинаковые данные с вынесенными каталогами. Версии чередовались, по три открытия каждой. Перед каждым открытием очищалось хранилище сайта, HTTP-кэш вкладки отключался.

| Медиана от начала навигации | 1.14.1 | Рабочая сборка |
|---|---:|---:|
| Загружены три обязательные библиотеки | 2,33 с | 1,27 с |
| Появился первый непустой слой спутников | 3,79 с | 3,50 с |
| Готов первый набор текстур фотоглобуса | 8,26 с | 7,70 с |

Ранняя загрузка библиотек сохраняет порядок исполнения. Манифесты глобуса и облаков запрашиваются параллельно. Для стартового вида глобуса установка PWA и загрузка подробной географии начинаются после первого набора текстур, при задержке источника ожидание ограничено восемью секундами. В режиме 2D и текстовом каталоге своя последовательность загрузки.

Метрики слоёв сняты через `MARKS` из браузерного стенда `scripts/perf/perf.mjs`. Время готовности фотоглобуса по трём открытиям рабочей сборки составило 6,99–8,31 с. Физические устройства, мобильное покрытие и боевой сервер в этом сравнении не участвовали.

## Версия 1.14.1

Цель — сократить подготовку рельефа с сохранением результата. Разрешение текстур, DPR, размер сетки, освещение, пороги выбора тайлов и источники данных не снижались.

- Широты и долготы, синусы и косинусы вычисляются один раз на строку или столбец сетки. Для промежуточных значений используется Float64; запись в конечные Float32-атрибуты осталась прежней.
- Индексы треугольников записываются сразу в Uint32Array, без промежуточного массива чисел.
- Проекции общих углов и размеры тайлов сохраняются только на время текущего выбора. Между разными положениями камеры кэш не переносится.
- Невыбираемая поверхность не выдаёт цвет с alpha=255 без индекса слоя в проходе выбора. Готовый terrain cover сохраняет собственные цвета; обычный вид и проход определения глубины не меняются.

## Проверка

В корне публичного репозитория:

```sh
node tests/test_terrain.cjs index.html
node scripts/perf/terrain.cjs index.html
```

В исходном дереве вместо `index.html` укажите путь к шаблону страницы. Benchmark работает с функциями текущей страницы и настоящим GlobeViewport из закреплённой версии deck.gl, без запуска браузера. Для сравнения передайте ему отдельно сохранённую исходную страницу.

`tests/fixtures/terrain-1.14.0.json` содержит результаты прежней версии. Проверяются точные байты позиций, нормалей, UV, юбок и индексов треугольников на сетках 16, 32, 64 и 128, включая берег, отрицательные исходные высоты и полярные широты. Проверяется точный список и порядок выбранных тайлов для пяти видов, включая наклон, узкое окно и линию смены дат. Смена камеры не должна повторно использовать устаревшие проекции. Отдельная проверка ограничивает количество вызовов project в наклонном виде.

## Результаты 15 ноября 2026

Node 24 на одном компьютере, три чередующихся запуска каждой версии; каждый запуск включает прогрев и 12 измерений построения синтетического тайла 256×256 на сетке 128×128. Медиана медиан: 140,0 мс до изменения и 84,9 мс после, сокращение примерно на 39%. VM и среда Node отличаются от browser worker, поэтому абсолютные времена не являются временем обработки тайла в браузере.

Для наклонного GlobeViewport 1600×1000 (42.5° E, 43.2° N, zoom 9.5, pitch 55°, bearing 30°) список из 140 тайлов не изменился; число проекций уменьшилось с 560 до 192. Меньшее число проекций само по себе не доказывает соответствующий рост FPS.

В браузере одинаковые пять перемещений камеры воспроизводили десять ошибок `Picked non-existent layer` на исходной версии и ни одной на исправленном варианте. Проверяются также выбор спутника, 2D/3D и зум. Сглаженный FPS-индикатор не показал устойчивого прироста в тяжёлом наклонном виде; основной подтверждённый выигрыш — подготовка сетки и сокращение повторных вычислений.

Загрузка новых высотных тайлов также зависит от источника и серверного кэша. Предварительная загрузка соседних областей в эту версию не добавлялась: без измерения пользы она увеличила бы трафик. Библиотечные предупреждения `terrain_map` при инициализации требуют отдельной проверки; исправление ошибки выбора не объявляется их исправлением.

Реальный телефон, p95 времени кадра и полный CPU/GPU-профиль в этой проверке не измерялись. Для следующей итерации нужны одинаковые сцены и настройки, раздельный замер нового и повторного участка, время готовности всех видимых тайлов и кадры у горизонта. Браузерный стенд `scripts/perf/perf.mjs` требует отдельного запуска и не подменяется этим CPU-тестом.

## English

Version 1.14.1 preserves texture resolution, DPR, mesh detail, lighting and tile selection. Mesh generation reuses row/column calculations and writes triangle indices directly into a typed array; shared tile corner projections are cached only within one selection.

The commands above verify byte-identical geometry against 1.14.0 and run a CPU-only benchmark. Three alternating runs on Node 24 reduced the median 128×128 mesh generation time from 140.0 to 84.9 ms (about 39%). These VM timings are not browser-worker timings. A tilted 1600×1000 view kept the same 140 tiles while reducing corner projections from 560 to 192.

Five browser drags produced ten invalid-picking errors before the fix and none in the corrected variant. No sustained FPS improvement was established for the heavy tilted view. Real-phone performance, frame-time p95 and full CPU/GPU profiles remain unmeasured. Speculative tile prefetching was not added, and initialization warnings about terrain_map are not claimed to be fixed.
